## 1. Ringkasan Eksekutif

Tahap 1 membangun seluruh fondasi PageLabs: monorepo, frontend shell, shared components, backend job pipeline, tool registry, dan satu vertical slice end-to-end menggunakan **Merge PDF** sebagai referensi.

Tahap 1 **tidak** membangun seluruh tool. Hanya **Merge PDF** yang harus berfungsi penuh. Tool lain hanya terdaftar di registry sebagai placeholder "Coming soon".

**Definisi sukses Tahap 1:** Merge PDF berjalan end-to-end di staging (upload → process → download → purge), lulus checklist `DESIGN.md` §10, dan semua shared components dapat dipakai ulang oleh tool berikutnya tanpa modifikasi.

**Prinsip desain yang mengikat seluruh Tahap 1:**
- **Whitespace di atas segalanya.** Setiap layar harus terasa lapang. Jarak antar elemen besar. Konten tidak boleh memenuhi viewport.
- **Simpel.** Tidak ada elemen dekoratif. Tidak ada ilustrasi. Tidak ada teks panjang.
- **Teks minimal.** Setiap label, deskripsi, dan pesan harus ≤ 2 baris. Jika lebih, potong.
- **Flat, full-rounded, shadowless, neutral dark.** Sesuai `DESIGN.md` §2.

## 5. Backend Requirements

### 5.1 API Gateway

Base URL: `/api/v1`

Endpoint yang harus ada di Tahap 1:

| Method | Path | Fungsi |
|---|---|---|
| POST | `/jobs` | Buat job baru |
| GET | `/jobs/:id` | Polling status |
| GET | `/jobs/:id/result` | Redirect ke signed download URL |
| DELETE | `/jobs/:id` | Cancel/purge manual |
| GET | `/health` | Health check |

Request `POST /jobs`:
```json
{
  "tool": "merge-pdf",
  "files": [
    { "url": "signed-upload-url-1", "name": "a.pdf", "size": 12345 },
    { "url": "signed-upload-url-2", "name": "b.pdf", "size": 67890 }
  ],
  "options": {
    "outputFilename": "merged.pdf",
    "addBookmarks": true
  }
}
```

Response:
```json
{
  "jobId": "uuid",
  "status": "queued",
  "pollUrl": "/api/v1/jobs/uuid"
}
```

### 5.2 Upload Flow

Karena Tahap 1 belum punya autentikasi, upload menggunakan **signed upload URL** dari endpoint tambahan:

| Method | Path | Fungsi |
|---|---|---|
| POST | `/uploads/sign` | Minta signed upload URL untuk satu file |

Request:
```json
{ "filename": "a.pdf", "size": 12345, "contentType": "application/pdf" }
```

Response:
```json
{ "uploadUrl": "https://...", "fileUrl": "https://...", "expiresAt": "..." }
```

Frontend upload langsung ke `uploadUrl` (PUT), lalu pakai `fileUrl` di `POST /jobs`.

### 5.3 Job Model (PostgreSQL)

```sql
CREATE TABLE jobs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tool TEXT NOT NULL,
  status TEXT NOT NULL CHECK (status IN ('queued','processing','validating','completed','failed')),
  files JSONB NOT NULL,
  options JSONB,
  result_url TEXT,
  result_size BIGINT,
  error_code TEXT,
  error_message TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  started_at TIMESTAMPTZ,
  completed_at TIMESTAMPTZ,
  expires_at TIMESTAMPTZ NOT NULL
);

CREATE INDEX idx_jobs_status ON jobs(status);
CREATE INDEX idx_jobs_expires ON jobs(expires_at);
```

`expires_at` = `created_at + 2 jam`.

### 5.4 Job Lifecycle

```
POST /jobs
  → insert row status='queued'
  → enqueue BullMQ job { jobId }
  → return { jobId, status: 'queued' }

Worker picks up:
  → update status='processing', started_at=NOW()
  → download files ke tmpdir
  → execute recipe (merge: qpdf --empty --pages ... --)
  → validasi output (page count > 0, size > 0, MIME=application/pdf)
  → upload ke S3, dapat result_url
  → update status='completed', completed_at=NOW(), result_url, result_size
  → shred tmpdir

On error:
  → update status='failed', error_code, error_message (sanitized)
  → shred tmpdir

Purge cron (setiap 10 menit):
  → DELETE FROM jobs WHERE expires_at < NOW() AND status IN ('completed','failed')
  → hapus file di S3 sesuai key
```

Timeout: worker kill setelah 300 detik, update status='failed' dengan `error_code='TIMEOUT'`.

### 5.5 Worker — Merge PDF Recipe

```python
def merge_pdf(job):
    files = job.files  # list of local paths setelah download
    output = tmpdir / "output.pdf"
    cmd = ["qpdf", "--empty"]
    for f in files:
        cmd.extend(["--pages", str(f), "1-z"])
    if job.options.get("addBookmarks"):
        # qpdf tidak support bookmark native per file tanpa script tambahan
        # fallback: pakai pikepdf untuk menambahkan outline setelah merge
        pass
    cmd.extend(["--", str(output)])
    subprocess.run(cmd, check=True, timeout=250)

    if job.options.get("addBookmarks"):
        add_bookmarks(output, files)

    return output
```

Validasi output:
- `qpdf --check output.pdf` → exit 0.
- Page count > 0 (via `pikepdf`).
- Size > 0.

Rename output sesuai `options.outputFilename` (sanitize: strip path, keep alphanumeric + dash + underscore + dot, force `.pdf`).

### 5.6 Validasi Input (API Layer)

Sebelum enqueue, API wajib memvalidasi:

| Aturan | Error |
|---|---|
| `tool` ada di registry | `INVALID_TOOL` |
| Tool = "merge-pdf" (Tahap 1 hanya ini) | `TOOL_NOT_AVAILABLE` |
| Jumlah file ≥ 2 dan ≤ 20 | `INVALID_FILE_COUNT` |
| Setiap file size ≤ 100MB | `FILE_TOO_LARGE` |
| Setiap file URL valid dan accessible | `INVALID_FILE_URL` |
| Setiap file MIME = application/pdf (via HEAD) | `INVALID_FILE` |
| `options` sesuai schema tool | `INVALID_OPTIONS` |

Semua error return HTTP 400 dengan `{ error_code, error_message }`.

### 5.7 Rate Limiting

Middleware di API:
- Anonymous (Tahap 1 semua anonymous): 10 job/jam per IP.
- Implementasi: Redis counter dengan TTL 1 jam.
- Response 429: `{ error_code: "RATE_LIMITED", error_message: "Too many requests. Try again later." }`

### 5.8 Logging

Structured JSON, satu baris per event:

```json
{"ts":"2026-01-01T00:00:00Z","level":"info","event":"job.created","job_id":"...","tool":"merge-pdf","file_count":2,"total_size":123456}
{"ts":"...","level":"info","event":"job.completed","job_id":"...","duration_ms":4500,"result_size":234567}
{"ts":"...","level":"error","event":"job.failed","job_id":"...","error_code":"PROCESSING_FAILED"}
```

**Dilarang** log: nama file asli, isi file, password, signed URL lengkap.

### 5.9 Security

- Semua endpoint HTTPS di staging/production.
- Signed URL expiry: 15 menit.
- Temp file di `tmpfs` jika tersedia, jika tidak di volume terenkripsi.
- Shred temp file: `shred -u` (Linux) atau `rm -P` (macOS dev).
- Password (jika ada di tool lain nanti): memory-only, tidak pernah log atau DB.
- CORS: hanya origin frontend yang diizinkan.

## 7. Merge PDF — Spesifikasi Fungsional Lengkap

Karena Merge PDF adalah satu-satunya tool fungsional di Tahap 1, spesifikasinya harus eksplisit.

### 7.1 UI State Machine

```
idle
  → files.length < 2: process button disabled
  → files.length >= 2: process button enabled

processing
  → drop zone disabled
  → file chips tidak bisa di-remove
  → process button disabled + label "Merging…"
  → ProgressCard tampil

completed
  → ProgressCard hilang
  → ResultCard tampil
  → "Process another" reset ke idle

failed
  → ProgressCard hilang
  → ErrorAlert tampil di atas process button
  → process button re-enabled
  → files tetap ada untuk retry
```

### 7.2 Opsi

| Opsi | Tipe | Default | Validasi |
|---|---|---|---|
| `outputFilename` | string | `merged.pdf` | 1-100 char, alfanumerik + `-_.`, wajib `.pdf` |
| `addBookmarks` | boolean | `false` | — |

### 7.3 Validasi Client-Side

Sebelum upload:
- Setiap file MIME `application/pdf` atau ekstensi `.pdf`.
- Setiap file ≤ 100MB.
- Total file ≤ 20.
- Total size ≤ 500MB.

Jika gagal: toast error, file tidak ditambahkan.

### 7.4 Validasi Server-Side

Lihat §5.6.

### 7.5 Output

- File `.pdf` tunggal.
- Ukuran = jumlah halaman semua file input.
- Metadata: title = `outputFilename`, author = kosong, producer = `PageLabs`.
- Jika `addBookmarks = true`: satu outline entry per file input, label = nama file asli (tanpa `.pdf`).

### 7.6 Test Case Wajib

| # | Skenario | Ekspektasi |
|---|---|---|
| 1 | 2 PDF valid, 1 halaman masing-masing | Output 2 halaman, bisa dibuka di Acrobat |
| 2 | 20 PDF valid | Output 20 halaman, sukses |
| 3 | 1 PDF | Process button disabled, tidak bisa submit |
| 4 | 21 PDF | Toast error "Maximum 20 files" |
| 5 | File .txt di-rename .pdf | Toast error "Invalid file type" (magic byte check) |
| 6 | PDF 101MB | Toast error "File too large" |
| 7 | PDF corrupt | Job failed dengan `PROCESSING_FAILED`, ErrorAlert tampil |
| 8 | `addBookmarks = true` | Output punya outline 2 entry (untuk 2 file) |
| 9 | `outputFilename = "../etc/passwd"` | Sanitized jadi `passwd.pdf` atau fallback `merged.pdf` |
| 10 | 2 PDF valid, salah satu password-protected | Job failed dengan pesan "One file is password-protected" |

## 8. Non-Functional Requirements

### 8.1 Performance

| Metrik | Target |
|---|---|
| LCP halaman home | < 1.5s |
| LCP halaman tool | < 1.5s |
| Upload throughput | > 5 MB/s (dev) |
| Merge 2 × 5MB PDF | < 5s end-to-end |

### 8.2 Reliability

- Job retry: 1x otomatis untuk error transient (network), tidak retry untuk error validasi.
- Worker crash: job tetap di queue, di-reprocess setelah worker restart (BullMQ stalled job handling).
- Purge cron: setiap 10 menit, hapus job expired + file S3.

### 8.3 Security

- Semua endpoint staging: HTTPS wajib.
- Signed URL expiry 15 menit.
- Tidak ada file name di log.
- Tidak ada isi file di log.
- Rate limit aktif.
- CORS restricted.
- Security header: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`.

### 8.4 Accessibility

- Semua checklist `DESIGN.md` §7 lulus.
- axe-core: 0 violation di home dan tool page.

### 8.5 Code Quality

- TypeScript strict mode, 0 `any` (kecuali di library boundary dengan komentar).
- ESLint 0 warning.
- Prettier formatted.
- Setiap shared component punya minimal 1 unit test.
- Merge PDF recipe punya integration test (upload 2 PDF → download → verify page count).

## 10. Out of Scope — Explicit

AI Agent **tidak boleh** mengerjakan hal-hal berikut di Tahap 1, meskipun terlihat "mudah":

- Tool selain Merge PDF (hanya placeholder).
- Autentikasi, signup, login.
- Pricing page.
- Analytics atau tracking.
- Blog.
- Email notification.
- API key.
- Webhook.
- Dashboard usage.
- Dark mode otomatis berbasis sistem (hanya manual toggle).
- Animasi transisi antar halaman.
- Loading skeleton (cukup spinner inline).
- Fitur "recently used".
- Favorite tools.
- Search tool.
- Keyboard shortcut.
- i18n.
- PWA manifest.
- SEO meta tag (beyond title dan description dasar).
- Favicon custom (pakai default dulu).
- Cookie banner.

Jika AI Agent menemukan kebutuhan yang tidak tercantum, **tanyakan**, jangan improvisasi.

## 11. Urutan Eksekusi yang Disarankan untuk Antigravity

Ikuti urutan ini untuk meminimalkan rework:

```
1. Init monorepo + pnpm workspace + CI
2. Setup docker-compose (Postgres, Redis, MinIO)
3. Backend: API skeleton + health endpoint
4. Backend: DB schema + migration
5. Backend: /uploads/sign
6. Backend: /jobs (create, get, result, delete) tanpa worker
7. Worker: skeleton + queue consumer
8. Worker: merge-pdf recipe + integration test lokal
9. Frontend: Next.js init + Tailwind + shadcn init
10. Frontend: tokens (globals.css) + Manrope + theme toggle
11. Frontend: shared components (8 buah)
12. Frontend: home page + tool registry render
13. Frontend: placeholder tool page
14. Frontend: merge-pdf tool page (wire ke API)
15. End-to-end test merge-pdf di lokal
16. Deploy staging
17. Verifikasi seluruh acceptance criteria §9
18. Serahkan ke user untuk review
```

Setiap langkah harus hijau sebelum lanjut. Tidak ada paralelisasi kecuali dua langkah tidak saling bergantung (misal: shared components dan worker recipe bisa paralel).
