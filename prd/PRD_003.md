## 1. Ringkasan Eksekutif
Tahap 3 berfokus pada optimasi ukuran file, perbaikan file rusak, ekstraksi teks dari hasil scan (OCR), dan konversi standar arsip (PDF/A). 
Semua tool di tahap ini menerima **1 file input**.

**Prinsip Desain:** Wajib mengikuti `DESIGN.md` (Whitespace, Shadowless, Flat, Full-Rounded). Jangan menggunakan teks yang terlalu panjang. UI harus sangat simpel.

## 2. Spesifikasi Tool & UI

Perbarui `packages/shared/src/tools.ts` (set `available: true`) dan buat halaman UI baru untuk masing-masing tool.

### 3.1 Compress PDF (`/tools/compress-pdf`)
**Deskripsi UI:** "Reduce file size."
**Opsi UI:**
- RadioGroup / Select untuk tingkat kompresi:
  - "Less compression" (Kualitas tinggi, ukuran sedang)
  - "Recommended" (Seimbang - Default)
  - "Extreme compression" (Kualitas rendah, ukuran terkecil)
**Backend Recipe (Python & Ghostscript):**
- Gunakan Ghostscript via subprocess.
- `Less`: `gs -sDEVICE=pdfwrite -dPDFSETTINGS=/prepress -dCompatibilityLevel=1.7 ...`
- `Recommended`: `gs -sDEVICE=pdfwrite -dPDFSETTINGS=/ebook ...`
- `Extreme`: `gs -sDEVICE=pdfwrite -dPDFSETTINGS=/screen ...`
- **PENTING:** Setelah kompresi, pastikan file output valid. Jika Ghostscript gagal, fallback ke `qpdf` (kualitas *lossless*).

### 3.2 Repair PDF (`/tools/repair-pdf`)
**Deskripsi UI:** "Fix broken PDFs."
**Opsi UI:** Tidak ada opsi (langsung proses).
**Backend Recipe (Python):**
- Coba perbaiki menggunakan `qpdf --replace-input` atau `pikepdf`.
- Jika `qpdf` gagal (file terlalu rusak), fallback menggunakan Ghostscript untuk me-render ulang PDF (`gs -sDEVICE=pdfwrite ...`).
- Jika keduanya gagal, return error aman `PROCESSING_FAILED` ("File is severely damaged and cannot be repaired").

### 3.3 OCR PDF (`/tools/ocr-pdf`)
**Deskripsi UI:** "Make scanned PDFs searchable."
**Opsi UI:**
- Select bahasa (Default: "English", opsi: "Indonesian", "Spanish", dll).
- Toggle: "Add text layer only" (jika aktif, halaman asli dipertahankan).
**Backend Recipe (Python & OCMyPDF):**
- Gunakan library `ocrmypdf` via subprocess.
- Perintah dasar: `ocrmypdf --skip-text -l <lang> input.pdf output.pdf`
- **PENTING:** Jika file yang di-upload sudah memiliki *text layer*, worker harus mendeteksinya dan mengembalikan error `INVALID_OPTIONS` ("This PDF already contains searchable text").
- Waktu pemrosesan OCR bisa memakan waktu lebih dari 300 detik (timeout default). **Naikkan timeout job khusus untuk OCR** menjadi 600 detik di `apps/worker`.

### 3.4 PDF to PDF/A (`/tools/pdf-to-pdfa`)
**Deskripsi UI:** "Convert to archival format."
**Opsi UI:**
- Select tingkat PDF/A: "PDF/A-2b" (Default) atau "PDF/A-3b".
**Backend Recipe (Python & Ghostscript):**
- Gunakan Ghostscript dengan profil warna ICC.
- Perintah dasar: `gs -dPDFA=2 -dBATCH -dNOPAUSE -sColorConversionStrategy=UseDeviceIndependentColor -sDEVICE=pdfwrite -dPDFACompatibilityPolicy=1 -sOutputFile=output.pdf input.pdf`
- Verifikasi output jika memungkinkan menggunakan library `pikepdf` (pastikan metadata PDF/A terpasang).

## 3. Backend Requirements (Updates)

1. **Docker Worker (`apps/worker`):**
   - Tambahkan `ghostscript` dan `ocrmypdf` ke dalam `Dockerfile` worker.
   - Pastikan *language packs* untuk Tesseract terinstal (minimal `eng` dan `ind`).
2. **API Gateway (`apps/api`):**
   - Perbarui Tool Registry (set `available: true` untuk 4 tool ini).
   - Tambahkan penanganan timeout yang lebih lama untuk job OCR di Queue (BullMQ).
